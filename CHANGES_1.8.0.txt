e2xray 1.8.0
============

Fixed: a configuration whose server is IPv6 parsed but could never start
-------------------------------------------------------------------------
IPv6 *traffic* has been captured since 1.5.0, but a *server* reached over IPv6
was a different matter. A link such as

    vless://<id>@[2001:db8::1]:443?security=tls&type=ws#V6

parsed correctly and produced a valid core configuration, and then the start
failed with:

    Start failed [DNS_FAILED]: Could not resolve the proxy server: 2001:db8::1

`resolve_server_ips` classified anything that was not a plain dotted-quad as a
host name and asked for A records only, so an IPv6 literal resolved to nothing
and a host name published only as AAAA did too.

  * An IPv6 literal now resolves to itself.
  * Host names are additionally looked up for AAAA, so a v6-only server works.
  * The two families are tracked separately in the runtime state
    (`SERVER_IPS` and `SERVER_IPS6`), and a start is allowed when either is
    present.
  * When both are known, IPv4 is dialled; the address pinning added in 1.4.0
    now understands v6 as well, so a v6-only host name pins to its AAAA record
    while the name is still used for TLS SNI and the Host header. An address
    that is already an IPv6 literal is left exactly as it is.
  * In TUN mode the v6 server gets the same /128 host route in the tunnel's
    table that the v4 server has always had.
  * The card-sharing bypass list stays IPv4-only on purpose, so a v6 peer can
    never end up in an iptables rule that could not express it.

Fixed: the IPv6 block could cut off an IPv6-only server
---------------------------------------------------------
Where IPv6 cannot be captured - the TPROXY and REDIRECT backends - 1.5.0
blackholes it so nothing leaks. That blackhole is a plain route and applied to
the core's own sockets too, so a server reachable only over IPv6 was cut off by
the very rule meant to protect the user. The core's fwmark now bypasses the
block through the same private table the IPv4 path uses, exactly as it does in
TUN mode: everything else stays blocked, the transport still gets out.
